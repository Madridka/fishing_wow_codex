# WoW Fishing

Оконное приложение ищет поплавок, сопровождает центр пробки и нажимает **правую**
кнопку после подтверждённого резкого движения. По умолчанию задержка клика — 0,75 с.

## Запуск

Готовое приложение: `dist/WoWFishing.exe`. Исходники: `python main.py`.
После нажатия «Начать рыбалку» есть три секунды, чтобы переключиться в игру.
Способность «Рыбалка» должна быть назначена на клавишу `1`.
Остановка — кнопка «Остановить», **F8** или закрытие окна.
Также сохранён аварийный механизм PyAutoGUI: перемещение курсора в угол экрана.

## Центр и поклёвка

Первоначальный поиск использует сохранённые эталоны поплавка из `calibration`.
Затем сопровождается локальное изображение **той же пробки**, а не заново
выбирается поплавок на всём экране. Сопоставление яркости и границ переносит
умеренные изменения освещения. После потери трек восстанавливается рядом
с последним центром; большой скачок требует новой стабилизации.

Движение оценивается по исходным координатам центра, до сглаживания мыши.
Сначала не менее 0,8 с и 12 кадров изучается обычное движение. Порог адаптируется
к шуму и размеру поплавка; значение в окне задаёт нижнюю границу (по умолчанию 6 px).
Нужны минимум три подтверждения на протяжении не менее 0,1 с.
Дрожание 1–2 px, одиночная ошибка координат и равномерный дрейф не дают подсечку.
Мышь использует медиану трёх координат и зону покоя 5 px.

В окне доступны три режима:

- **Движение центра** — основной, цвет брызг не участвует в решении.
- **Брызги (прежний режим)** — сохранён предыдущий алгоритм.
- **Движение + брызги** — нужны оба подтверждения.

Задержка правого клика регулируется от 0,5 до 1 с. Во время неё координата
подсечки обновляется; остановка отменяет клик. При длительной потере центра
перед подсечкой клик также отменяется.

## Новый заброс и потеря центра

После правого клика бот ждёт исчезновения старого поплавка: отсутствие
подтверждается несколькими кадрами на протяжении минимум 0,4 с. Новый заброс
не выполняется поверх видимого старого. Дополнительная минимальная пауза после
подсечки — **3 с**, в окне её можно изменить от 1 до 10 с.

При потере центра бот пробует расширенный поиск рядом с последней целью до 2 с.
После восстановления заново изучается спокойное движение, чтобы скачок
восстановленных координат не стал ложной поклёвкой. Если восстановить центр
не удалось, старый заброс отменяется клавишей `Esc`, затем бот ждёт исчезновения
поплавка и делает паузу перед повтором. Аналогично обрабатываются таймауты поиска
и ожидания поклёвки.

Если после клика поплавок остаётся видимым более 6 с, улов не засчитывается:
бот нажимает `Esc` и ещё раз ждёт исчезновения. Если поплавок не исчезает и после
этого, приложение останавливает рыбалку и пишет причину в журнал.
При повторном запуске сначала завершается обнаруженный предыдущий заброс.

## Счётчик

В окне отдельно показаны **успешные подсечки**, забросы и потери центра.
В журнале строка `СЧЁТЧИК` также содержит число правых кликов и подсечек без
подтверждения. Счётчик успешных подсечек увеличивается один раз за цикл, только
после правого клика и подтверждённого исчезновения поплавка.
Отмена клавишей `Esc`, потеря центра, таймаут и сам клик ничего к нему не прибавляют.

Это оценка по поведению поплавка: получение предмета в инвентарь и число предметов
добычи не проверяются. Счётчик сохраняется при «Остановить» → «Начать» в одном окне,
при закрытии приложения начинается новый сеанс. Очистка окна журнала его не сбрасывает.

Камера во время заброса должна оставаться неподвижной: резкое перемещение камеры
тоже сдвигает поплавок на экране. Начальный поиск откалиброван под имеющуюся модель
поплавка; другая модель или существенно иной масштаб потребуют новых эталонов.
Работа на реальных видеозаписях из разных локаций пока не проверена.

## Журнал

В окне видны забросы, найденный центр, шум, адаптивный порог, отклонение,
подтверждение, клик и ошибки. Строка состояния трекинга обновляется раз в секунду.
Сохраняются `fishing.log` и до трёх предыдущих файлов по 1 МБ.
Последняя поклёвка записывается в `last_bite_debug.png` с траекторией центра.
В режиме брызг сохраняется прежнее сравнение «до/после».

Для исходников файлы находятся рядом с `main.py`, для `.exe` — рядом с ним.
Если эта папка недоступна для записи, используется `%LOCALAPPDATA%/WoWFishing`.
Кнопка очистки удаляет только строки из окна, файл журнала сохраняется.

## Проверка и сборка

```powershell
python -m pip install -r requirements.txt
python -m unittest -v
python main.py --self-test
```

Тесты не управляют настоящей мышью и не запускают рыбалку в игре.
`--self-test` проверяет скрытое окно, журнал, библиотеки и встроенные эталоны;
результат `SELF-TEST OK` записывается в журнал, код завершения — 0.

Сборка одного Windows `.exe`:

```powershell
python -m pip install -r requirements-build.txt
python build_exe.py
.\dist\WoWFishing.exe --self-test
```

Сборка включает PNG из `calibration`, Tk и Windows-бэкенды клавиатуры/мыши.
Пути ресурсов и файлов пользователя разделены согласно
[документации PyInstaller](https://pyinstaller.org/en/stable/runtime-information.html).
`build_exe.py` также умеет использовать PyInstaller из локальной `.build-tools`.

## Устройство

- `main.py` — запуск, DPI, журнал на диске, F8 и зависимости.
- `app_ui.py` — окно, настройки, очереди журнала и состояния.
- `bobber_vision.py` — первоначальный поиск, локальный трекер, прежние брызги.
- `fishing_logic.py` — настройки, анализ движения, сглаживание мыши, цикл рыбалки.

Другие настройки (монитор, таймауты, область поиска, клавиша заброса) находятся
в `BotConfig`. Старые изображения `bobbers` сохранены и не подмешиваются
к текущим эталонам автоматически. Результаты ревью — в `REVIEW.md`.
