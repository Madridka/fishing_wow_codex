Калибровка для маленького тёмного поплавка с перьями вправо.

Основной режим теперь определяет поклёвку по движению центра пробки; устройство
и настройки описаны в корневом `README.md`. Ниже сохранено описание алгоритма
**«Брызги (прежний режим)»**, доступного через переключатель в окне.

- `bobber_idle.png` — фрагмент локального `bobber_not_found.png` с дождём, без поклёвки.
- `bobber_bite.png` — приложенный пользователем кадр с брызгами (фото 3/4).

Поиск привязан к синему перу и проверяет расположение красного пера,
пробки и кольца. Центры пробки заданы в `BobberDetector.REFERENCE_CENTERS`.
Старые крупные эталоны из `bobbers` сохранены, текущий поиск использует эту папку.

Перед проверкой брызг детектор изучает фон не менее 0,6 секунды и 10 кадров.
Затем сравнивает одну фиксированную область экрана с этим фоном. Постоянные блики,
кольцо и небольшой сдвиг координат не должны считаться новыми брызгами.

Для поклёвки нужны одновременно:

- минимум 1,4% ярких контрастных пикселей и превышение обычного уровня с учётом его шума;
- минимум 0,8% новых ярких пикселей за пределами запомненных бликов;
- как минимум три отдельные частицы, распределённые вокруг пробки;
- подтверждение минимум на трёх кадрах в течение не менее 0,12 секунды.

В режиме брызг смещение и потеря поплавка сами по себе не вызывают клик. При короткой
потере до четырёх кадров брызги проверяются на последнем известном месте.
После длительной потери или большого перемещения фон изучается заново.
Курсор во время ожидания находится на пробке и следует за её перемещением.
Дрожание координат на 1–2 пикселя не вызывает движения мыши. Начальный фон
изучается уже после наведения курсора, с учётом постоянной подсветки.

При подтверждённой поклёвке в корне проекта сохраняется `last_bite_debug.png`:
слева спокойный фон, справа сработавший кадр, снизу — число новых частиц.
Файл перезаписывается при следующем срабатывании.

Офлайн-проверка без запуска игры и управления мышью:

```powershell
python -m unittest -v test_bobber_vision
```

Статичные кадры не заменяют проверку на живой анимации: длительность брызг,
освещение и эффекты воды могут потребовать дальнейшей подстройки.
